Yes, I’ve read both. It’s a 2D heat equation solver in C++ with MPI, run on a cluster you build yourselves: one Ubuntu VM per teammate, all linked with Tailscale. The work runs over 4 weeks with checkpoints along the way.

Order to work in:

The math tasks first. They’re in the background-notes PDF. The ones the code depends on are 3.2, 3.4, 5.2 (the update rule), 6.3 (the stability limit r ≤ 1/4), 7.2 (the convergence study) and 8.2 (the communication model). You hand these in as a separate PDF.
Part 0, the cluster:
Ubuntu Server 24.04 VMs (Multipass is the quickest way on Windows), same user name on every VM, e.g. mpi.
Install openmpi-bin and Tailscale, then set up passwordless SSH between every pair of VMs.
Run mpirun with the hostfile, using --mca oob_tcp_if_include tailscale0 --mca btl_tcp_if_include tailscale0.
Write a ping-pong benchmark (8 B to 16 MB) and fit latency and bandwidth.
Part 1, the serial solver: one contiguous std::vector<double>, two arrays swapped each step, and the flags --case/--N/--r/--steps/--out/--decomp. Then run test V for the convergence study. This plus Part 0 is checkpoint C1.
Part 2, strips: split rows across processes with ghost rows, exchanged via MPI_Sendrecv and MPI_PROC_NULL. The output must match the serial version byte for byte. (C2)
Part 3, blocks: a 2D grid of processes (MPI_Cart_create) exchanging halos in 4 directions.
Part 4, performance study: time the runs and explain them with the latency/bandwidth model. Slowdowns on small grids are expected, and explaining them counts as much as a speed-up.
Part 5 (CUDA) is optional. Skip it unless you have time left.
Start now with: the Part 0 setup on your own VM, plus the serial solver, which you can write on your PC right away.
